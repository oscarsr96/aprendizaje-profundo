SECCIÓN 1

El problema: overfitting cuando hay pocos datos

Imagina que entrenas un clasificador de gatos vs perros con solo 200 imágenes. La red neuronal, que tiene millones de parámetros, puede memorizar cada píxel de cada foto. En training alcanza 99% de acierto… pero en test un patético 68%.

Esto es overfitting: el modelo aprende los datos de entrenamiento en vez de aprender el concepto. Mira lo que pasa en el entrenamiento de una red pequeña cuando no tenemos suficientes datos:

💡
Sin augmentation la validation loss sube mientras la training loss baja → la red memoriza. Con augmentation las dos curvas bajan juntas: el modelo generaliza.
Las tres formas de combatir el overfitting
① Más datos

La solución ideal, pero etiquetar datos cuesta tiempo y dinero. A veces es imposible (imágenes médicas raras, defectos industriales…).

② Regularización

Dropout, weight decay, early stopping… Todo ayuda, pero no elimina la causa: la falta de variabilidad en los datos.

③ Data Augmentation

Creamos datos sintéticos plausibles a partir de los que ya tenemos. Gratis, potente y a menudo es la técnica que más impacto tiene.

SECCIÓN 2

¿Qué es Data Augmentation? La intuición

Data Augmentation (aumento de datos) es el proceso de generar nuevas muestras de entrenamiento aplicando transformaciones a las existentes, de forma que la etiqueta se conserve.

Un gato girado 15° sigue siendo un gato. Un "7" al que le añades un poco de ruido sigue siendo un "7". La red neuronal ve muchas variantes del mismo concepto y aprende a ser invariante a lo que no debería importar (rotación, iluminación, posición…) y sensible a lo que sí importa (forma, estructura).

La idea formal

Sea un dataset D = {(x₁, y₁), …, (xₙ, yₙ)} y una familia de transformaciones T tales que T(x) preserva la etiqueta. El dataset aumentado es:

D' = { (T(xᵢ), yᵢ) : T ∈ T, i = 1…n }

En la práctica, aplicamos T aleatoriamente cada vez que la imagen entra a la red durante el training. Así, cada época, la red ve una versión ligeramente distinta. El dataset efectivo se vuelve prácticamente infinito.

🧠
Regla de oro: una transformación válida es aquella que no cambia la etiqueta correcta. Si giras 90° un "6", se convierte en un "9" → eso rompe la etiqueta.

Galería de técnicas básicas para imágenes

Las transformaciones más usadas (la "dieta básica" de cualquier pipeline de visión por computador). Cada tarjeta muestra el efecto aplicado sobre la misma imagen base:

Galería en vivo
🔁
Cada transformación se aplica con parámetros aleatorios. Recarga la página (o pulsa el botón) para ver otras muestras.
Cheatsheet: qué hace cada una
Flip horizontal/vertical

Refleja la imagen. Seguro para gatos/coches/caras desde arriba; peligroso para texto, dígitos o asimetrías semánticas (izquierda vs derecha).

Rotation

Rota un ángulo aleatorio en un rango (típicamente ±15-30°). Cuidado con los bordes: rellena con cero, reflejo o extensión.

Random crop / zoom

Recorta una región aleatoria y la reescala. Enseña a la red a reconocer el objeto aunque esté parcialmente fuera de cuadro.

Color jitter

Altera brillo, contraste, saturación y tono. Simula distintas cámaras y condiciones de luz.

Gaussian noise

Añade ruido aleatorio a cada píxel. Mejora robustez frente a sensores ruidosos y ataques adversariales.

Blur

Suaviza la imagen (Gaussian blur, motion blur). Útil cuando en test esperas imágenes ligeramente desenfocadas.

SECCIÓN 5

Técnicas avanzadas: Mixup, CutMix y Cutout

A partir de 2017 surgieron técnicas que van más allá de "transformar una sola imagen". Sorprendentemente, funcionan aún mejor:

Mixup — interpolación lineal entre muestras

Mixup combina dos imágenes xₐ, x_b y sus etiquetas yₐ, y_b:

x' = λ·xₐ + (1-λ)·x_b    y' = λ·yₐ + (1-λ)·y_b

¿Una imagen "mitad gato mitad casa" con etiqueta "0.5 gato + 0.5 casa"? Suena raro, pero regulariza la red: la obliga a comportarse linealmente entre muestras y evita predicciones demasiado confiadas.
CutMix — recorta y pega un parche de otra imagen

En vez de mezclar todos los píxeles (como Mixup), pega un rectángulo de la imagen B sobre A. La etiqueta se pondera por el área ocupada.

Aleatorio automático
—

Cada click genera un nuevo parche aleatorio. La etiqueta se recalcula proporcionalmente al área del parche.

Cutout — haz click para tapar regiones

Cutout tapa un rectángulo con ceros (o gris medio). Fuerza a la red a no depender de una sola región y aprender features más distribuidas.

Haz click sobre la imagen
Tamaño del parche60 px

Variantes: Random erasing usa valores aleatorios en vez de ceros. GridMask aplica una cuadrícula de cutouts.

¿Por qué estas técnicas funcionan tan bien?
  • Regularización implícita: al forzar a la red a no sobreajustarse a un solo ejemplo, actúa como un dropout espacial.
  • Smoothing de etiquetas: Mixup evita predicciones "demasiado seguras" que son frágiles.
  • Robustez: redes entrenadas con CutMix son más resistentes a oclusiones parciales en test.
SECCIÓN 6

Data Augmentation en texto (NLP)

Augmentar texto es más delicado: cambiar una palabra puede cambiar el sentido de la frase. Aún así, hay técnicas útiles:

Frase base
El restaurante es excelente y el servicio fue muy rápido esta noche.
Activa una técnica arriba para ver la transformación…
Técnicas populares en NLP
EDA (Easy Data Augmentation)

4 operaciones simples: synonym replacement, random insertion, random swap, random deletion. Baseline sorprendentemente efectivo.

Back-translation

Traduces es → en → es. Obtienes una paráfrasis semánticamente equivalente pero léxicamente distinta. Excelente para clasificación.

Mask-filling con BERT

Enmascaras una palabra y usas un modelo como BERT para predecir alternativas que encajen en el contexto.

Paraphrasing con LLMs

Pides a un modelo generativo: "reescribe esta frase". Muy potente, pero caro y puede introducir sesgos.

⚠️ Cuidado en tareas sensibles al significado exacto: en NER, sentiment analysis fino o tareas con negación, incluso un sinónimo puede cambiar la etiqueta ("bueno" → "aceptable" ≠ "bueno" → "excelente").
SECCIÓN 7

Datos tabulares: SMOTE y el problema del desbalance

En datasets tabulares (fraude, diagnóstico médico, churn…) el problema típico es el desbalance de clases: el 98% de los datos son "no fraude" y solo el 2% son "fraude". Una red ingenua predice siempre "no fraude" y acierta un 98% — inútil.

SMOTE (Synthetic Minority Over-sampling Technique) genera muestras sintéticas de la clase minoritaria interpolando entre vecinos próximos:

SMOTE en vivo
● Clase mayoritaria ● Clase minoritaria × Muestras sintéticas
k vecinos5
Cantidad de sintéticas0
📐
Para cada minoritaria xᵢ, elige un vecino xⱼ y crea un punto en xᵢ + α·(xⱼ - xᵢ) con α aleatorio en [0,1]. Es data augmentation lineal en el espacio de features.
Variantes importantes
  • Borderline-SMOTE: solo genera muestras cerca de la frontera de decisión (donde realmente ayudan).
  • ADASYN: genera más muestras donde la clasificación es más difícil.
  • SMOTE-NC: variante para features categóricas mezcladas con numéricas.
  • GAN-based: redes generativas producen muestras tabulares sintéticas (CTGAN, TVAE).
SECCIÓN 8

Cuándo NO usar Data Augmentation (o cómo meter la pata)

Augmentation no es gratis. Aplicada mal, empeora el modelo. Aquí los errores clásicos:

❌ Flip en texto / dígitos
Un "6" volteado es un "9". "casa" invertida deja de ser una palabra. Respeta la semántica.
❌ Rotación fuerte en caras / matrículas
Las caras tienen una orientación canónica. Una cara girada 180° casi nunca aparece en producción — no es una augmentation "realista".
❌ Color jitter en detección de tumores
El color puede ser una pista diagnóstica. Alterarlo introduce señal espuria.
❌ Augmentation en validation/test
Solo se augmenta el training set. Validation y test deben reflejar la distribución real de despliegue.
❌ Demasiada intensidad
Rotar 180° un gato boca abajo puede ser válido, pero mezclado con zoom extremo y ruido masivo, la red ya no aprende del concepto.
❌ No revisar las muestras
Siempre visualiza un batch de imágenes augmentadas. Si tú no reconoces la clase, la red tampoco podrá.
El proceso correcto
  1. Entrena un modelo base sin augmentation → fija tu baseline.
  2. Añade augmentations de una en una y mide validation accuracy.
  3. Visualiza al menos 16 muestras augmentadas antes de entrenar.
  4. Ajusta la intensidad hasta que la curva de validation deje de bajar.
  5. Si todo falla, prueba AutoAugment o RandAugment (búsqueda automática de pipelines).

Los mismos 5 augmentations básicos (flip, rotation, crop, color jitter, normalize) en los frameworks más usados:

# PyTorch: torchvision.transforms.v2 (API moderna) from torchvision.transforms import v2 import torch train_tf = v2.Compose([ v2.RandomResizedCrop(size=224, scale=(0.7, 1.0)), v2.RandomHorizontalFlip(p=0.5), v2.RandomRotation(degrees=15), v2.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2), v2.ToDtype(torch.float32, scale=True), v2.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]), ]) # En val/test: SIN augmentation aleatoria val_tf = v2.Compose([ v2.Resize(256), v2.CenterCrop(224), v2.ToDtype(torch.float32, scale=True), v2.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]), ]) train_ds = ImageFolder("data/train", transform=train_tf) val_ds = ImageFolder("data/val", transform=val_tf)
# Keras: capas de augmentation integradas en el modelo import tensorflow as tf from tensorflow.keras import layers data_aug = tf.keras.Sequential([ layers.RandomFlip("horizontal"), layers.RandomRotation(0.1), # ±10% × 2π rad layers.RandomZoom(0.2), layers.RandomContrast(0.2), layers.RandomBrightness(0.2), ], name="augmentation") model = tf.keras.Sequential([ layers.Rescaling(1./255), data_aug, # solo activa en training layers.Conv2D(32, 3, activation="relu"), layers.MaxPooling2D(), # ... resto del modelo layers.Dense(num_classes, activation="softmax"), ]) # Las capas Random* se comportan como identidad en inference — perfecto model.compile(optimizer="adam", loss="sparse_categorical_crossentropy") model.fit(train_ds, validation_data=val_ds, epochs=30)
# Albumentations: la librería más rápida y completa import albumentations as A from albumentations.pytorch import ToTensorV2 train_tf = A.Compose([ A.RandomResizedCrop(height=224, width=224, scale=(0.7, 1.0)), A.HorizontalFlip(p=0.5), A.Rotate(limit=15, p=0.5), A.ColorJitter(brightness=0.2, contrast=0.2, p=0.5), A.GaussNoise(var_limit=(5, 30), p=0.3), A.CoarseDropout(max_holes=8, max_height=32, max_width=32, p=0.5), # cutout A.Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225)), ToTensorV2(), ]) # Uso: augmented = train_tf(image=np_image)["image"] # Mixup manual (Albumentations no lo incluye como transform estándar) def mixup(x1, y1, x2, y2, alpha=0.2): lam = np.random.beta(alpha, alpha) x = lam * x1 + (1 - lam) * x2 y = lam * y1 + (1 - lam) * y2 return x, y
⚡
Recomendación: para proyectos serios de visión, usa Albumentations (hasta 3× más rápida que torchvision) con el dataset en PyTorch. Para prototipos rápidos, las capas de Keras son las más cómodas.

CIERRE

Resumen ejecutivo

  1. Data augmentation genera nuevas muestras aplicando transformaciones que preservan la etiqueta.
  2. Es la forma más barata de combatir el overfitting cuando tienes pocos datos.
  3. Las técnicas básicas (flip, rotation, crop, color jitter, noise) funcionan en casi cualquier problema de visión.
  4. Las avanzadas (Mixup, CutMix, Cutout) añaden aún más regularización.
  5. En NLP las más usadas son EDA y back-translation.
  6. En tabular, SMOTE y sus variantes atacan el desbalance de clases.
  7. La regla de oro: visualiza siempre un batch augmentado. Si tú no reconoces la clase, la red tampoco.
📚
Para ir más allá: busca AutoAugment (Google, 2019), RandAugment, TrivialAugment y los papers originales de Mixup (Zhang et al., 2017) y CutMix (Yun et al., 2019).
