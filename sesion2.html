— 01 —

El ecosistema
Python.

Antes de escribir una red conviene saber qué herramientas hay sobre la mesa y para qué sirve cada una.

El lenguaje del deep learning

¿Por qué Python?

Python no es el lenguaje más rápido, pero se ha convertido en el estándar de hecho del machine learning por una razón: pega muy bien las piezas.

Escribes código sencillo y legible, mientras el trabajo pesado lo hacen librerías escritas en C/C++ y CUDA que aprovechan la CPU y la GPU. Tú piensas; la máquina calcula.

  • Sintaxis simple: prototipas una idea en minutos.
  • El mayor ecosistema de librerías científicas que existe.
  • Frameworks maduros (TensorFlow, PyTorch) con toda la comunidad detrás.
  • Cuadernos interactivos (Jupyter, Colab) para experimentar y ver resultados al instante.
  • Gratis para usar GPU en la nube con Google Colab.

Idea clave: en deep learning casi nunca programas las operaciones matemáticas a mano. Llamas a librerías que ya las tienen optimizadas.

El kit de herramientas

Las librerías que vas a usar.

NUMPY

NumPy

La base de todo. Arrays n-dimensionales (tensores) y operaciones matemáticas vectorizadas y rápidas.

PANDAS

pandas

Carga y limpieza de datos tabulares: leer CSV, filtrar, agrupar. El paso previo casi siempre.

PLT

Matplotlib

Visualización: ver los datos, dibujar la curva de pérdida y entender qué está pasando.

SKLEARN

scikit-learn

ML clásico y utilidades: dividir en train/test, escalar datos, métricas de evaluación.

TF·KERAS

TensorFlow / Keras

El framework de deep learning. Keras es su API de alto nivel: construir y entrenar redes con pocas líneas.

TORCH

PyTorch

La alternativa, dominante en investigación. Más explícito. Hoy usaremos Keras, pero conviene sonarte.

Primer arranque

Instalar e importar.

Con un solo comando instalas el stack. En Google Colab ya viene todo preinstalado: abres un cuaderno y a programar.

La convención es importar siempre con los mismos alias (np, pd, plt). Verás ese patrón en todo el código del mundo.

# 1) Instalar (terminal / celda de Colab)
pip install tensorflow numpy pandas matplotlib

# 2) Importar con los alias de siempre
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

# 3) Comprobar versión
print(tf.__version__) # → 2.x

Consejo: trabaja siempre dentro de un entorno virtual (venv o conda) o en Colab. Así cada proyecto tiene sus propias versiones y no se pisan entre sí.

— 02 —

NumPy y los
tensores.

Todo lo que entra y sale de una red neuronal es un tensor. Entender la pieza básica te ahorra la mitad de los errores.

La pieza básica de los datos

Un tensor es un array.

"Tensor" suena complejo, pero es solo un array de números con un número de dimensiones (su rango). Una imagen, una tabla o un sonido se representan así.

  • 0D · escalar — un número suelto: 7
  • 1D · vector — una lista: [1, 2, 3]
  • 2D · matriz — una tabla: filas × columnas
  • 3D — una imagen en color: alto × ancho × canales
  • 4D — un lote de imágenes
import numpy as np

escalar = np.array(7)
vector  = np.array([1, 2, 3])
matriz  = np.array([[1, 2], [3, 4]])

print(matriz.shape) # (2, 2)
print(matriz.ndim) # 2 → es 2D
print(matriz.dtype) # int64
Por qué NumPy es rápido

Operaciones vectorizadas.

En lugar de recorrer los números con un bucle, NumPy aplica la operación a todo el array de una vez, en código compilado. Es más corto de escribir y mucho más rápido.

Las redes neuronales son, por dentro, sumas y multiplicaciones de matrices a gran escala. Por eso esto importa tanto.

a = np.array([1, 2, 3])
b = np.array([10, 20, 30])

a + b # [11, 22, 33]
a * 2 # [2, 4, 6]
a @ b # 140 (producto escalar)

# Sin bucles, sin esfuerzo:
X = np.random.randn(1000, 784)
W = np.random.randn(784, 128)
salida = X @ W # (1000, 128)

Esa última línea (X @ W) es exactamente lo que hace una capa densa por dentro: multiplicar las entradas por los pesos.

— 03 —

Tu primera
red neuronal.

Vamos a clasificar dígitos manuscritos (MNIST), el "hola mundo" del deep learning, de principio a fin.

Paso 1 · Los datos

El dataset MNIST.

70.000 imágenes de dígitos escritos a mano (0–9), en blanco y negro de 28×28 píxeles. La tarea: dada una imagen, predecir qué dígito es.

Keras lo trae listo. Viene ya dividido en entrenamiento (60.000) y test (10.000), con sus etiquetas.

from tensorflow.keras.datasets import mnist

(X_train, y_train), (X_test, y_test) = \
    mnist.load_data()

X_train.shape # (60000, 28, 28)
y_train[0] # 5 (la etiqueta)
X_train.max() # 255 (intensidad del píxel)

Regla de oro: el modelo solo aprende del conjunto de entrenamiento. El de test se reserva para medir si de verdad generaliza a datos que nunca ha visto.

Paso 2 · Preparar los datos

Aplanar y normalizar.

Dos transformaciones antes de entrenar. Primero aplanamos cada imagen de 28×28 a un vector de 784 números, porque nuestra primera red espera un vector de entrada.

Segundo, normalizamos: dividimos entre 255 para que cada píxel quede entre 0 y 1. Las redes entrenan mucho mejor con valores pequeños y centrados.

# 28x28 = 784 → vector; 0-255 → 0-1
X_train = X_train.reshape(60000, 784)
X_train = X_train.astype("float32") / 255

X_test = X_test.reshape(10000, 784)
X_test = X_test.astype("float32") / 255

X_train.shape # (60000, 784)
X_train.min(), X_train.max() # 0.0, 1.0
Paso 3 · El modelo

Apilar capas.

Un modelo Sequential es una pila de capas. Aquí dos capas Dense (totalmente conectadas):

  • Una capa oculta de 128 neuronas con relu (no linealidad).
  • Una capa de salida de 10 neuronas con softmax → una probabilidad por dígito.
from tensorflow.keras import layers, models

model = models.Sequential([
  layers.Dense(128, activation="relu",
            input_shape=(784,)),
  layers.Dense(10, activation="softmax"),
])

model.summary() # resumen de capas y parámetros

relu en las capas ocultas y softmax en la salida multiclase es la combinación por defecto. Si esto te suena de la sesión anterior, es justo el perceptrón llevado a varias capas.

Paso 4 · Compilar

Las tres decisiones.

Compilar es decirle al modelo cómo va a aprender. Son las tres piezas del bucle de entrenamiento que vimos en teoría.

optimizer

"adam"

Cómo ajusta los pesos para reducir el error. Adam es una opción robusta por defecto.

→ el "cómo corregir"

loss

sparse_categorical_crossentropy

Mide cuánto se equivoca. La adecuada para clasificación multiclase con etiquetas enteras.

→ el "cuánto me equivoco"

metrics

["accuracy"]

Lo que miramos los humanos para juzgar el modelo. No se usa para entrenar, solo para informar.

→ el "cómo voy"
model.compile(
  optimizer="adam",
  loss="sparse_categorical_crossentropy",
  metrics=["accuracy"],
)
Paso 5 · Entrenar

Una línea: fit.

fit ejecuta el bucle de entrenamiento por ti: forward → pérdida → ajuste, repetido sobre lotes (batches) durante varias pasadas completas (epochs).

  • epochs=5 — 5 pasadas por todos los datos.
  • batch_size=128 — ajusta los pesos cada 128 ejemplos.
  • validation_split=0.1 — reserva un 10% para vigilar que no se sobreajuste.
history = model.fit(
  X_train, y_train,
  epochs=5,
  batch_size=128,
  validation_split=0.1,
)

# Epoch 1/5 loss: 0.34 acc: 0.90
# ...
# Epoch 5/5 loss: 0.07 acc: 0.98

Verás la pérdida bajar y la precisión subir época a época. Eso es, literalmente, la red aprendiendo.

Paso 6 · Evaluar y predecir

¿De verdad generaliza?

El momento de la verdad: medimos el modelo sobre el conjunto de test, que no ha visto nunca. Si la precisión sigue alta, ha aprendido de verdad y no se ha limitado a memorizar.

Con predict obtenemos, para una imagen nueva, las 10 probabilidades; argmax nos da el dígito más probable.

# Evaluar sobre datos nuevos
test_loss, test_acc = model.evaluate(X_test, y_test)
print(f"Precisión test: {test_acc:.3f}")
# → ~0.975

# Predecir un dígito concreto
probs = model.predict(X_test[:1])
probs.argmax() # → 7 (el dígito predicho)

Si la precisión en entrenamiento fuera muy alta y la de test mucho más baja, tendríamos sobreajuste: el modelo memoriza en vez de generalizar. Lo veremos en próximos temas.

Todo junto

Tu primera red, completa.

import tensorflow as tf
from tensorflow.keras import layers, models, datasets

# 1 · Datos
(X_train, y_train), (X_test, y_test) = datasets.mnist.load_data()
X_train = X_train.reshape(60000, 784).astype("float32") / 255
X_test  = X_test.reshape(10000, 784).astype("float32") / 255

# 2 · Modelo
model = models.Sequential([
  layers.Dense(128, activation="relu", input_shape=(784,)),
  layers.Dense(10, activation="softmax"),
])

# 3 · Compilar
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

# 4 · Entrenar y evaluar
model.fit(X_train, y_train, epochs=5, batch_size=128)
model.evaluate(X_test, y_test) # ~97% de acierto

Menos de 15 líneas para clasificar dígitos con un 97% de acierto. Ese es el poder de las librerías modernas.

— 04 —

Errores
comunes.

Casi todos los tropiezos del primer modelo se repiten. Reconocerlos te ahorra horas.

Lo que falla la primera vez

Cuatro tropiezos típicos.

1

No normalizar

Entrenar con píxeles de 0 a 255 hace que la red apenas aprenda. Divide entre 255.

2

Shapes que no encajan

El error más frecuente. Imprime siempre .shape: la entrada del modelo debe coincidir con tus datos.

3

Loss equivocada

Clasificación ≠ regresión. Con etiquetas enteras usa sparse_categorical_crossentropy, no MSE.

4

Evaluar con datos de entrenamiento

Da una nota engañosamente alta. Mide siempre sobre el test, datos que el modelo no ha visto.

Resumen de la práctica

Tres ideas para llevarte.

01 · Librerías

No reinventes la rueda

Python pega piezas; NumPy y Keras hacen el cálculo pesado. Tú diseñas el experimento.

02 · Tensores

Todo es un array

Datos, pesos y predicciones son tensores. Vigilar las .shape evita la mayoría de los errores.

03 · La receta

Siempre el mismo esqueleto

Datos → modelo → compilar → fit → evaluate. Casi cualquier proyecto sigue ese guion.

Ya sabes qué es el deep learning y ahora también cómo se programa. El resto del curso es profundizar en cada una de estas piezas.
